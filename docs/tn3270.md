# TN3270

<p class="lede">Most mainframe workload still arrives as 3270 data streams. Testing it means
speaking the protocol, which k6 does through xk6-tn3270, a native Go implementation
of RFC 1576 and RFC 2355 with no external emulator process.</p>

## What the scripts cover

| Script | Target | What it measures |
| --- | --- | --- |
| `simbank-logon.js` | SimBank | Smoke test: connect, sign on, reach the menu |
| `simbank-browse.js` | SimBank | Account enquiry under a slow ramp |
| `simbank-transfer.js` | SimBank | A write transaction at a fixed arrival rate |
| `cics-transaction.js` | Your CICS region | Sign on with CESN, run a transaction, sign off |
| `tso-logon.js` | TSO | Logon and logoff as an availability probe |

You need a binary with the extension in it. See [install]({{ '/install/' | relative_url }}).

```bash
xk6 build v1.6.1 --with github.com/msradam/xk6-tn3270@v0.1.0
```

## Start with SimBank

[Galasa SimBank](https://galasa.dev) is the sample 3270 application that ships with
the Galasa test framework. It has a logon screen, a menu, an account enquiry, and a
funds transfer, and it runs in a JVM on a laptop with no mainframe involved. Prove
a script works there before pointing it at an LPAR.

```bash
git clone https://github.com/galasa-dev/simplatform.git
cd simplatform && ./build-locally.sh && ./run-locally.sh --server
```

```bash
k6 run -e TN3270_HOST=localhost -e TN3270_PORT=2023 \
  scripts/tn3270/simbank-logon.js
```

See `environments/simbank/README.md` in the repository.

## Field boundaries

3270 fields are fixed width, and typing into one auto-advances to the next
unprotected field only when the current field is filled exactly. A seven-character
user id in an eight-character field does not advance:

```javascript
session.type('IBMUSER');   // 7 chars in an 8-char field
session.tab();             // needed, the cursor did not move on
session.type('SYS1');
session.enter();
```

But on the transfer screen, where two nine-character account fields are both filled
exactly, no tab is needed:

```javascript
session.type(fromAccount);  // 9 of 9, cursor advances by itself
session.type(toAccount);    // same
session.type('10.00');
session.enter();
```

A script that assumes the wrong behaviour will work against one emulator and type
into the wrong field on another. `scripts/lib/tn3270.js` has a `fillFields` helper
that tabs only where it has to.

## Closing sessions

A 3270 gateway allocates a terminal per session, and terminal pools are finite in a
way that HTTP connection pools are not. If a check throws and the session is never
disconnected, the socket leaks until the iteration ends, and that shows up as an
exhausted terminal pool long before it shows up as a k6 error.

```javascript
export function withSession(fn, options = {}) {
  const session = openSession(options);
  try {
    return fn(session);
  } finally {
    session.disconnect();
  }
}
```

Every TN3270 sample wraps its session in this.

## Ramp rate

For the same reason, the browse script ramps over a minute rather than starting at
full VU count. A sharp ramp against a gateway measures the terminal pool rather
than the application.

```javascript
stages: [
  { duration: '1m',  target: 10 },
  { duration: '2m',  target: 10 },
  { duration: '30s', target: 0 },
],
gracefulRampDown: '30s',
```

Think time matters too. Real operators read the screen before pressing the next
key. Removing it turns the test into a protocol benchmark rather than a workload
model. Both are worth measuring; they answer different questions.

## Waiting on the screen

`waitForField()` blocks until the keyboard unlocks and an input field exists, which
is the signal that the host is ready for input. A fixed `sleep()` is not a
substitute: it either wastes time or reads the previous screen.

```javascript
session.sendCommand('BANK', true);   // type, enter, then waitForField
session.sendPF(1, true);             // PF1, then waitForField
```

`tn3270_wait_timeouts` counts the times that wait gave up. It belongs in your
thresholds at zero, because a wait timeout means the screen never came and every
check after it is measuring the wrong screen.

```javascript
thresholds: {
  tn3270_wait_timeouts: ['count == 0'],
  tn3270_connect_duration: ['p(95) < 5000'],
}
```

## Against your own CICS region

`cics-transaction.js` is deliberately generic. It signs on with `CESN`, runs the
transaction you name, checks for a string you name, and signs off with
`CESF LOGOFF`. All three are IBM-documented transactions.

```bash
k6 run \
  -e TN3270_HOST=cics.example.com -e TN3270_PORT=23 \
  -e TN3270_USER=TESTID -e TN3270_PASSWORD="$PASSWORD" \
  -e CICS_TRAN=MYTX -e CICS_EXPECT='ENQUIRY COMPLETE' \
  -e CICS_TPS=5 \
  scripts/tn3270/cics-transaction.js
```

`setup()` fails if either variable is unset. Abends are counted separately from
protocol failures by matching the terminal messages CICS sends:

```javascript
if (screen.includes('DFHAC2206') || screen.includes('DFHAC2001')) {
  transactionAbends.add(1);
}
```

Start with a read-only enquiry.

## TSO logons

`tso-logon.js` is an availability check: if TSO accepts a logon, the system is up
and RACF is answering. Run it on a schedule rather than under load.
Each logon allocates a TSO address space, and a burst will hit `MAXUSERS` long
before it stresses anything interesting.

One thing to watch: a single RACF id cannot log on twice. If several VUs share one,
you get `IKJ56425I` and a misleading failure rate. The script warns when it sees it.

## TLS

```javascript
session.connectTLSWithOptions('mainframe.example.com', 992, {
  caCert: open('/etc/ssl/internal-ca.pem'),
  clientCert: open('/etc/ssl/client.pem'),
  clientKey: open('/etc/ssl/client.key'),
  minVersion: '1.3',
});
```

The cipher allow-list is restricted to AEAD suites with forward secrecy. Set
`TN3270_TLS=true` to have `scripts/lib/tn3270.js` use TLS.
